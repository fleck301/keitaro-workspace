# Проверка решения

## Автоматически

`python -m pytest -q` — 11 тестов. Тесты запускаются на временных БД с Alembic-миграцией, без обращения к внешним сервисам.

Покрытие сценариев:

- создание кампании, проверка страны и справочников до внешних изменений;
- частичное создание с сообщением ID и выключенной кампанией;
- локальное добавление, фиксация, удаление, архив и возврат;
- отмена новых связей и восстановление последнего подтверждённого состояния;
- сохранение черновиков после повторного создания приложения;
- удаление связи снаружи и последующий возврат;
- устаревшая вкладка, конфликт перед Push, запрещённая запись с другого origin;
- сохранение фильтров, лендингов и других полей при Push, включая внешние изменения;
- ошибки реального HTTP-клиента и отсутствие повторных POST при таймауте;
- ровно 100% при количестве офферов от 1 до 200, фиксации и некорректные веса.

## Реальный тестовый Keitaro — 20 ноября 2026

Через интерфейс приложения создана кампания `test_goncharenko_workspace_20261120`, ID **216694**:

- домен ID 1813, группа ID 10332, источник ID 836;
- поток **1331924**: страна PT, редирект на Google;
- поток **1331925**: резервный, оффер ID 18813, вес 100%.

Проверены: создание и включение кампании после двух потоков, локальная фиксация веса, Push с частичным PUT списка офферов, пометка связи архивной в черновике, блокировка отправки пустого состава, отмена и повторный Fetch. Keitaro подтвердил отправку; повторный Fetch вернул ожидаемый состав.

В выданном аккаунте список доступных офферов содержал один элемент. Поэтому добавление нескольких разных офферов, сохранение архива после реального удаления связи и перераспределение остатка проверены в отдельном локальном DEMO и автоматических тестах. Чужие кампании не изменялись, глобальные офферы не создавались.
